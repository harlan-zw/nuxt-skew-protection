[Netlify](https://netlify.com) provides native skew protection on all plans. It routes protected requests to the production deploy that issued the client's token, while that deploy remains available. See [Netlify skew protection](https://docs.netlify.com/deploy/deploy-overview/#skew-protection).

Use native affinity alone when old sessions should remain on their deploy until the next hard navigation:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    preset: 'netlify'
  },
  skewProtection: {
    mode: 'native',
    bundleAssets: false,
    trackBuildMetadata: true
  }
})
```

Native mode disables module update discovery. Use hybrid mode below when the app should prompt or reload after a new production deploy.

`NETLIFY_SKEW_PROTECTION_TOKEN` enables native mode automatically during a Netlify production build. Explicit `mode: 'native'` makes the requirement clear and fails early when the platform cannot provide native affinity.

The module enables native mode only when Netlify provides `NETLIFY_SKEW_PROTECTION_TOKEN`. Native affinity retains the complete old deploy, so module asset bundling is redundant. Build metadata remains enabled for release history and rollback detection.

## Framework API contract

The module writes `.netlify/v1/skew-protection.json`. Netlify's current schema has two fields:

```json [.netlify/v1/skew-protection.json]
{
  "patterns": [
    "^/_nuxt/.*\\.(css|js|mjs|wasm|woff|woff2)$",
    "(^|/)_payload\\.json$",
    "^/api/.*"
  ],
  "sources": [
    {
      "type": "cookie",
      "name": "netlify-skew-token"
    }
  ]
}
```

`patterns` contains regular expressions for paths that require affinity. `sources` accepts `cookie`, `header`, and `query` entries. The `name` selects the cookie, header, or query parameter containing the token. You may enable multiple sources together. See [Netlify's Frameworks API](https://docs.netlify.com/build/frameworks/frameworks-api/#netlifyv1skew-protectionjson).

The token comes from `NETLIFY_SKEW_PROTECTION_TOKEN` during builds and Functions. Edge Functions can also read `context.deploy.skewProtectionToken`. The token identifies one deploy; a plain deploy ID is not the documented token contract.

The cookie source is the safest browser default. The server sets `netlify-skew-token` from the runtime token, then the browser includes it without exposing token plumbing to application fetch calls. A header source requires adding the token to every protected client request. A query source exposes the value in URLs and logs.

Netlify ignores affinity signals on hard navigation, then serves the latest production deploy. This prevents a persistent cookie from pinning a browser forever. Branch deploys, Deploy Previews, and deploy permalinks bypass native skew protection.

## Keep update discovery unpinned

The native contract has positive `patterns`; it has no exclusion field. Avoid a catch-all pattern such as `^/.*`.

These paths must resolve against the current production deploy:

- `/_nuxt/builds/latest.json`
- `/_nuxt/builds/meta/*.json`
- `/__skew/sse`
- `/__skew/ws`
- Any custom `basePath` equivalents

The module validates generated patterns against these control plane paths. The sample asset patterns do not match build metadata JSON. If the app has a custom `app.baseURL`, `buildAssetsDir`, or skew `basePath`, generated patterns and exclusions use those resolved paths.

## Hybrid update discovery

Native affinity keeps application requests on the old deploy. Update discovery must deliberately bypass that affinity so the old client can learn about the new deploy.

Use hybrid mode when the latest manifest is reachable through an unpinned same-origin route or a separate update origin:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  skewProtection: {
    mode: {
      mode: 'hybrid',
      discoveryURL: '/_nuxt/builds/latest.json'
    },
    updateStrategy: 'polling',
    bundleAssets: false
  }
})
```

Polling is the safe default for Netlify Functions. Current streaming Functions have a 10 second execution limit, which causes frequent SSE reconnects. See the [Netlify Functions API](https://docs.netlify.com/build/functions/api/#streaming-responses). Use an external update adapter when you need instant cross-instance notification.

## Platform limits

- Native affinity applies only to production context.
- Netlify CLI deploys require version 23.11.0 or newer.
- Production Password Protection disables skew protection when all deploys are protected.
- A retained deploy remains addressable only for clients holding its token. Align deploy retention with the longest supported browser session.
