[Vercel](https://vercel.com) native skew protection routes requests carrying `__vdpl` to the deployment that issued the cookie. When `VERCEL_SKEW_PROTECTION_ENABLED=1` and `VERCEL_DEPLOYMENT_ID` are available, the module defaults to native mode.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: { preset: 'vercel' },
  skewProtection: {
    mode: 'native',
    bundleAssets: false,
    trackBuildMetadata: true
  }
})
```

The module owns the document response cookie and disables Nitro's Vercel cookie rule. This guarantees one `__vdpl` setter and scopes its path to `app.baseURL`. Native mode disables update discovery because a same-origin `builds/latest.json` request is pinned to the old deployment.

See [Vercel Skew Protection](https://vercel.com/docs/skew-protection) and [Nitro's Vercel integration](https://github.com/nitrojs/nitro/pull/3850).

## Hybrid discovery

Use hybrid mode when active sessions should receive a prompt or automatic reload. `discoveryURL` must bypass Vercel deployment affinity, usually through a separate update hostname:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  skewProtection: {
    mode: {
      mode: 'hybrid',
      discoveryURL: 'https://updates.example.com/_nuxt/builds/latest.json'
    },
    updateStrategy: 'polling',
    bundleAssets: false
  }
})
```

The update origin must return the current Nuxt app manifest and allow requests from the application origin. Publish the manifest only after the new deployment is serving traffic.

## Portable mode

Set `mode: 'portable'` to disable Vercel affinity and retain old client assets through the module's storage seam. This does not retain old Functions or server behavior. Use persistent storage available across Vercel builds; a local filesystem cache alone is insufficient.
